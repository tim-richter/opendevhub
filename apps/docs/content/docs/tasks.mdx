**New task** starts agent work from a prompt, without opening the opencode tab. It's on the Overview and project pages and in `⌘K`, or press `n`.

By default a task creates a [worktree](/docs/worktrees) on a branch named after the prompt's first line (`-2`, `-3`… when the name is taken), starts a session there and sends the prompt. **Main checkout** runs it in the project folder instead. **Environment: Own container** runs it in its [own container](/docs/worktrees#own-containers).

![The New task dialog with a prompt, a new worktree in the shared container, and two models to compare](./images/new-task.webp)

## Compare models

**Compare with another model** runs the same prompt on up to four models, each in its own worktree (`<branch>-<model>`). The task page shows each variant's status, cost, tokens and changes, with a Review link. Each variant's cost and tokens include its subagents, and the task's total above the cards includes discarded variants.

![A task page comparing two variants side by side, each with its branch, cost, tokens and changes](./images/task-variants.webp)

**Pick this one** hides the other variants. It can also remove their worktrees and branches, after a confirmation that lists any uncommitted changes.

## Where tasks are stored

A task is stored in its sessions' opencode metadata (`metadata.opendevhub`), so it survives restarts of opendevhub and of the container.

## Review and publish

Each checkout has a **Review** tab that shows the changes. Its toolbar stays at the top while you scroll: the branch, which changes are shown, how far ahead and behind the base it is, and whether it has uncommitted changes. **Uncommitted** (the default) shows the checkout's `git diff`, new files included. Switch to the base (for example **main**) to see everything since the branch left it, committed or not; click the base again to pick another. Each checkout remembers its choice, and when nothing is uncommitted but the branch has commits, the review offers to compare with the base. By default a diff shows only the changed lines with a few lines around them; click an "unmodified lines" bar to expand it, or switch to the full file. You can also show the old and new versions side by side, and hide the changed-files tree. These choices are remembered.

Comment on a line with the **+** in the diff's gutter; the comments button collects them, takes general comments, and sends them all to a session. The **Git** menu commits, updates from the base, merges into the base, and [publishes](/docs/publish) the branch as a pull request; an action that can't run says why.
